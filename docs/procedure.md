# 作業手順（AI・手動共通）

判断ルールと完了基準は [rules.md](rules.md) に従う。AIの有無で成果物や品質基準は変えない。

## 開始条件

依頼者が対象リポジトリ／スナップショット、Java・既存C#の基準版、作業用の非公開保存先、実行可能な環境、対象.NET等のバージョン、委任範囲、仕様判断者と確認者を指定する。資料が足りない場合は、読める範囲を調査し、不足によって判断できない箇所を記録する。

## Phase 1：全体解析

1. [全体解析テンプレート](../templates/analysis.md)をコピーし、対象・基準版・解析担当を記録する。
2. Java・既存C#双方の全ソースを棚卸しする。ビルド定義、設定、入口、画面、業務処理、データアクセス、SQL、認証、共通部品、外部連携、テストまで構成と主要な呼び出しを解析する。自動生成物・依存物・バイナリー等の除外は理由を記録する。
3. 解析台帳で範囲ごとの確認方法・状態・未確認理由を残す。「全体解析」は数ファイルの抜き読みやディレクトリ名の推測だけで完了させない。
4. システム構成と大まかなJava/C#対応表を作る。未作成の移行先は「予定」、未調査の対応は「未確認」と区別する。
5. 入口・ルート・テンプレート・画面遷移から画面一覧を作る。画面IDを割り当て、対応するJava、既存C#、関連する共通処理を結び付ける。
6. 画面ごとに概要タスクを作り、共通依存・先行条件・不明点を整理する。共通処理の実装を複数画面へ重複計画しない。
7. Phase 1完了基準で自己点検し、基準版として保存する。未確認によって着手できない画面を明記する。

## Phase 2：画面単位の移行

1. 対象画面IDを指定し、全体解析、概要タスク、共通依存、既存の指示書・報告書を読む。
2. 関連Javaと既存C#を詳細調査する。入力、表示、業務条件、SQL、トランザクション、権限、遷移、異常時まで根拠をたどり、既存C#を再利用できるか確認する。
3. [指示書テンプレート](../templates/instruction.md)へ具体的なタスクを記入する。各タスクに親概要ID、根拠ソース、出力先、区分、依存、受入条件、検証IDを付ける。実装可能な単位に分け、単なる「画面を移行する」で済ませない。
4. 共通ルールに従って指示書を保存・確定する。範囲内は作業者が確定できる。未決の仕様は保留として切り出す。
5. [報告書テンプレート](../templates/report.md)を別ファイルに作り、確定指示書を固定版で参照する。依存順に実装し、タスクごとに結果を記録する。
6. 受入条件を検証し、タスク・Javaの根拠・C#の変更・検証を関連付ける。発見事項は別欄に記録し、既存問題をついでに直さない。タスク変更が必要ならCRと新しい指示書版を先に作る。
7. 未実施や失敗を含め全タスクを報告し、作業者の終了判定と再開に必要な情報を残す。全体解析の概略対応に差があれば新しい解析版へ反映し、旧版は残す。
8. 人間が根拠・差分・結果を確認し、必要な修正と再検証を行う。同じ受入条件を満たす修正は元タスクに追記し、仕様や受入条件を変える場合はCRを用いる。
9. 人間が画面完了基準で判定する。実装済みだけで完了にせず、共通処理を含む接続確認まで扱う。

共通処理を独立して実施する場合も同じ指示書・報告書を使い、対象IDを `COM-xxx` に置き換える。

## 手動で進める場合

上記の全ステップを人間の作業者が実行する。Phase 1ではIDEの参照検索やファイル検索で入口から処理をたどり、台帳へ記録する。Phase 2ではJava・既存C#・指示書を並べて読み、タスク順に実装する。

ビルド・テスト・ブラウザー操作は指示書の方法で実行し、ログや画面確認を非公開の証跡に保存する。自動テストを用意できない項目は再現可能な手動操作と期待値を具体化する。AIの会話履歴は成果物の代わりにせず、人間だけで指示書と報告書から再開できる状態を保つ。

## AIへの依頼例

パスと基準版を実案件用に置き換えて使用する。これらは依頼の入口であり、共通ルールの複製ではない。

### Phase 1

```text
AGENTS.md、docs/rules.md、docs/procedure.mdを読んでPhase 1を実施してください。
Java: <場所と固定版>、既存C#: <場所と固定版>。
対象範囲・除外・環境・委任範囲・判断者: <依頼情報>。
templates/analysis.mdを用い、<非公開保存先>/analysis-v1.mdに保存してください。
業務コードは変更せず、未確認箇所と解析の限界も記録してください。
```

### Phase 2

```text
AGENTS.md、docs/rules.md、docs/procedure.mdを読んでPhase 2を実施してください。
対象: <画面ID>。全体解析: <場所と固定版>。委任範囲・判断者: <依頼情報>。
関連ソースを調査し、<非公開保存先>/instruction-v1.mdを先に保存・確定してください。
範囲内の確定タスクを自律的に実施し、結果は別ファイルreport-v1.mdへ記録してください。
判断が必要なタスクは理由を残して保留し、独立したタスクは続行してください。
```

再開依頼では対象画面、指示書の固定版、直近の報告書と作業中ソース版を渡す。読込量を減らす場合も、対象の根拠・共通依存・未解決事項を省略しない。
